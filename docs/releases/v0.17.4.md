## Malformed-response recovery

Fix [#75](https://github.com/HsiangNianian/dsh-auto-continue/issues/75): `MALFORMED_RESPONSE` errors could be mistaken for permanent failures when their echoed tool arguments contained words such as `auth`, `permission`, `api_key` or `quota exceeded`

The classifier now recognizes that error code before matching permanent-error text. Explicit HTTP 401/403 failures are still blocked by the built-in rules, and custom retryable patterns retain their existing priority. Cooldown, backoff and consecutive-attempt limits still apply

The shared fix covers live errors, startup scans of loaded sessions and stored-session scans

## Upgrade

Let current work finish, stop DSH, then update the profile you use

```bash
dsh plugin --profile web add dsh-client-auto-continue@0.17.4
dsh web
```

Desktop app users should update through the app's Plugins page and restart the app, since it uses its own profile

- Reload open browser tabs after restarting
- Remove the temporary `malformed_response` and `non-whitespace character after json` entries added for #75 from **Custom retryable errors**, then Save; keep any unrelated custom entries
- For an older conversation already stuck on the error, send `Continue` once after updating — startup recovery only scans failures within its configured window, 15 minutes by default

## Validation

- Regression tests fail on 0.17.3 and pass with the fix: 17 error cases across live, loaded-session startup and stored-session scan paths
- Explicit HTTP 401/403 checks, genuine permanent failures, the consecutive-attempt cap and custom-pattern precedence
- Typecheck, build, full test suite and DSH runtime compatibility tests
- DSH 0.2.2-rc.1 core services with a local model adapter: the reported `auth` / `permission` cases recover without the workaround; real 401 and context-limit cases remain blocked

The model adapter injects deterministic failures; no real provider API or the reporter's private conversation was used
