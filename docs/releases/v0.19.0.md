Restart recovery works again on DSH 0.2.2, the composer switch no longer flickers off while it reconnects, the plugin speaks Russian, and subagents can now be resumed (opt-in)

## Restart recovery on DSH 0.2.2

Fixed in [#87](https://github.com/HsiangNianian/dsh-auto-continue/pull/87). If you restarted DSH 0.2.2 while a conversation was mid-turn, it just sat there afterwards, with nothing in the log saying why

0.2.2 waits for agents to shut down cleanly, so the interrupted turn now gets written to disk as "aborted by the host" instead of being left open. The startup scan read that as you pressing stop and skipped it. It now treats a host shutdown the same way it already did for child-session hand-off, so these conversations continue again after a restart

A stop you made yourself is still never resumed

## Composer switch

Reported in [#86](https://github.com/HsiangNianian/dsh-auto-continue/issues/86)

- The switch used to flip to off for a few seconds whenever the plugin's status connection dropped, for example when the host rebuilt its engine or the machine woke from sleep. It now keeps showing your setting, dimmed, until the connection is back, and reconnects in about half a second instead of three
- The host keeps the status connection alive with a small heartbeat, so proxies and security software are less likely to cut it while idle
- For a subagent, the button shows the mode it inherits from its main conversation
- The control is much smaller: one round ∞ button to turn it on or off, plus a small arrow for the mode menu. The mode name moved into the menu and the tooltip. The ∞ also replaces the borrowed refresh icon, which looked like "start over"

## Russian

Contributed in [#84](https://github.com/HsiangNianian/dsh-auto-continue/pull/84). With a `ru` or `ru-*` locale, the settings page, composer menu, notifications and the built-in continue, guard and loop texts are in Russian. If you use the default texts, the model now gets `Продолжай` instead of `Continue`

## Subagent recovery (opt-in)

Also from [#84](https://github.com/HsiangNianian/dsh-auto-continue/pull/84). **Resume subagent sessions** (`resumeSubagentSessions`, off by default) resumes a failed, cut-off or silent subagent while it is still loaded, using the main conversation's mode and its own retry budget

- Pausing or turning off the main conversation also stops its subagents
- Subagents still never run the autonomous loop, are never restarted by the loop guard, and aren't picked up by the startup scan
- It's off by default because DSH 0.2.2 usually closes a background subagent the moment it fails and tells the parent instead, so in most setups there's nothing left to resume. Turn it on if your subagents stay loaded, for example team members with work still running
- This doesn't replace **Wake child sessions after restart** from 0.18.0. The two work independently

## Upgrade

Let current work finish, stop DSH, then update the profile you use

```bash
dsh plugin --profile web add dsh-client-auto-continue@0.19.0
dsh web
```

Desktop app users should update through the app's Plugins page and restart the app, since it uses its own profile

- Reload open browser tabs after restarting so the new composer control loads
- Existing settings, session modes and pauses stay as they were. The only new setting is off by default
