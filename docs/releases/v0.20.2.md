The loop guard now catches a model that gets stuck repeating short lines

## Short-line floods get cut off

Reported by @Baka999 in [#93](https://github.com/HsiangNianian/dsh-auto-continue/issues/93), with the full event log of the session

A model stuck on a web form spent a minute and a half streaming one message, 92k characters of this:

```
Then: fill domain, go.

Writing.
```

The loop guard never fired. The check added for [#37](https://github.com/HsiangNianian/dsh-auto-continue/issues/37) only counted long paragraphs (40+ characters) repeated back to back. These lines are short, and they alternate, so no two neighbours ever match

Now the guard also looks at the last 40 paragraphs of the message being streamed. If 8 or fewer of them are different, the turn is cancelled and restarted with the loop text, like any other loop

- It doesn't matter how short the lines are or whether the repeats are next to each other
- If the model never writes a blank line, the lines of the runaway block are counted instead
- Lines with no letters or digits (`---`, code fences, lone braces) are ignored, so a long markdown report doesn't look like a loop
- The old check for long repeated paragraphs still works the same

The loop guard is on by default. If you turned it off, nothing changes

## Upgrade

Let current work finish, stop DSH, then update the profile you use

```bash
dsh plugin --profile web add dsh-client-auto-continue@0.20.2
dsh web
```

Desktop app users should update through the app's Plugins page and restart the app, since it uses its own profile

No settings changed

## Validation

- Typecheck, build (committed `lib/` reproduces byte for byte), the full regression suite and the DSH runtime compatibility tests
- Simulated hosts with default settings: the A/B flood with blank lines and with single newlines, and one short line repeated, all get cancelled. A long report with repeated rules, code fences and `Done.` lines, plus a 300-row table, does not
- Replayed against 0.20.1, none of those floods were cancelled

The other thing in #93, picking a turn back up when it ends on a broken tool call written out as text, is a separate feature and isn't in this release

Thanks @Baka999 for the detailed report. The line counts and the replay made this a quick fix
