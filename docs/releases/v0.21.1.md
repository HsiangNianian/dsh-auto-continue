If you stop a turn, the goal stays stopped, even when a retry kicks in afterwards

From @xiaobaifly7 in [#97](https://github.com/HsiangNianian/dsh-auto-continue/pull/97), again found on a real profile

## What went wrong

With **Resume goals** on, every continuation re-armed an `active` goal that was disarmed. That setting is meant for restarts, which disarm goals as a side effect. But DSH also disarms the goal when you stop an ordinary turn, and the plugin couldn't tell the two apart

So: you press stop, type "stop touching the network", the next turn hits a 429, the plugin retries it and re-arms the goal, and goal rounds keep going as if you never stopped

## What changed

Before re-arming, the plugin looks back through the session log. If your last stop is newer than the last goal `resume` or `create`, it leaves the goal off

- The failed turn is still retried, only the goal waits
- Resuming the goal yourself lifts the hold, since that's a newer `resume`
- Restarts, the loop guard and other host cancels don't count as your stop, so they re-arm like before
- Paused goals with **Resume paused goals** work the same as before
- If the log can't be read, nothing is re-armed

## Upgrade

Let current work finish, stop DSH, then update the profile you use

```bash
dsh plugin --profile web add dsh-client-auto-continue@0.21.1
dsh web
```

Desktop app users should update through the app's Plugins page and restart the app, since it uses its own profile. No settings changed

## Validation

- Typecheck, build, the full regression suite and the DSH runtime compatibility tests
- A new case in `tests/restart-resume-guards.mjs` retries a failed turn in five sessions: stopped by you, stopped then resumed, restarted, cancelled by a parent, and with no cancel cause. Only the first one keeps its goal off. It fails without the fix
