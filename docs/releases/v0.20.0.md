Failed subagents can now actually be resumed: the plugin brings the child back from its saved session instead of finding it already gone

## Cold resume for failed subagents

Contributed by @kesha4 in [#90](https://github.com/HsiangNianian/dsh-auto-continue/pull/90). This only applies with **Resume subagent sessions** (`resumeSubagentSessions`) turned on, which is still off by default

In 0.19.0 that setting rarely did anything: DSH closes a background subagent the moment one of its turns fails, so by the time the plugin wanted to send "continue", there was no subagent left to send it to

Now, when the child is already closed, the plugin asks DSH's subagent service to reopen it from its saved session and gives the continue message to the child itself

- The child uses its own cooldown and retry limit, the same as a live resume
- The main conversation is not woken up for this
- **Resume now** in a notification also works for a closed child

If DSH can't reopen the child (no saved session, the main conversation isn't loaded, or an older DSH without the service), the plugin tells the main conversation instead, with one short message per child at most every five minutes

- If the main conversation isn't loaded, the message waits until it is
- If the main conversation is busy recovering itself, the plugin stays quiet, since any new message would cancel that recovery. DSH already tells it which child failed

The hand-off goes in like any other continue message. It follows **Send continue messages with plugin source** and doesn't count as you typing, so it never resets the main conversation's retry or loop counters

## Upgrade

Let current work finish, stop DSH, then update the profile you use

```bash
dsh plugin --profile web add dsh-client-auto-continue@0.20.0
dsh web
```

Desktop app users should update through the app's Plugins page and restart the app, since it uses its own profile

- Reload open browser tabs after restarting
- No setting changed. If **Resume subagent sessions** is off, nothing behaves differently

## Validation

- Typecheck, build (committed `lib/` reproduces byte for byte), the full regression suite and the DSH runtime compatibility tests for `0.1.7`, `0.2.0`, `0.2.0-rc.2`, `0.2.1`, `0.2.1-rc.2` and `0.2.2-rc.1`
- Simulated hosts cover a successful cold resume, falling back to the hand-off when resume fails, no duplicate requests while one is in flight, Resume now on a closed child, waiting for an unloaded main conversation, staying quiet while it recovers, and the hand-off's message source
- @kesha4 checked it on a real host with the network cut: the failed child was reopened from its saved session, got the continue message, and eventually finished its task

The cold resume uses DSH's subagent control interface (`subagents.prompt`), which isn't a documented plugin API yet. The plugin checks it's there before calling it, and any error falls back to the hand-off
