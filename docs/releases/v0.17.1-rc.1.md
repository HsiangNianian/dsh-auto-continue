This prerelease fixes the extra continuation after a message rollback reported in [#69](https://github.com/HsiangNianian/dsh-auto-continue/issues/69), plus unnecessary retries when a prompt template variable is missing

It is available on the `next` dist-tag for testing, with `0.17.0` staying on `latest`

## Rollback compatibility

`@240xu/dsh-message-ops` wraps its rollback notice in a synthetic turn and step, which auto-continue previously mistook for a model turn with no visible response

- Recognize the plugin's `message-ops` turn marker and skip both silent recovery and autonomous followups for that turn
- Cancel automatic sends queued before the rollback
- Keep maintenance turns out of recovery success/failure statistics and preserve the existing retry budget
- Apply the same exclusion to startup scans of loaded and stored sessions, including an unfinished maintenance turn recovered after a restart
- Leave genuine silent model turns eligible for recovery, and allow normal turns carrying other reason values

The compatibility check targets the verified `message-ops` marker, since a nonempty `turn/start.reason` is not a general DSH contract for synthetic turns

## Missing prompt variables

With error classification enabled, errors such as `prompt variable "{{model}}" has no value for this assembly` now stop automatic retries and use the existing permanent-error notification

The missing variable still needs to be fixed in the host configuration; this patch prevents auto-continue from repeating the same failed assembly

Existing explicit retryable-error overrides still take precedence

## Validation

- Type checking, build, the full regression suite and existing DSH runtime compatibility tests
- Real DSH `0.2.1-rc.3` host components with published `@240xu/dsh-message-ops@0.11.8`, JSONL storage and its actual rollback HTTP endpoint
- Recovery and autonomous-loop modes: rollback adds no model call, where 0.17.0 added one after about three seconds
- Missing-model case: one failed turn and zero automatic retries, where 0.17.0 produced four failed turns; neither version reached the model in that case
- Focused tests for loaded/stored startup scans, pending-send cancellation, retry limits, other turn reasons and the stable/prerelease publishing paths
- Native settings form regression coverage added since 0.17.0

The rc.3 reproduction uses Node `26.8.2` and a deterministic model adapter, without external model calls or browser interaction

## Install the prerelease

Let active work finish and stop DSH, then update the plugin in the profile you use

```bash
dsh plugin --profile web add dsh-client-auto-continue@0.17.1-rc.1
dsh web
```

Reload the browser after restarting DSH

For the desktop app, install this exact version in its own profile and restart the app

To return to the stable release, install `dsh-client-auto-continue@0.17.0` in the same profile
