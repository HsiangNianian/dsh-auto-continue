Network outages no longer burn through the retry budget, the autonomous loop can be capped, and restarts can now hand interrupted subagent work back to its parent

## Offline hold

Requested in [#81](https://github.com/HsiangNianian/dsh-auto-continue/issues/81). Previously a dropped connection used up every retry in a few minutes, and nothing continued once the network came back

- Before retrying a network failure (`TRANSPORT`, `TIMEOUT`, DNS or connection errors), the host checks it is online: a non-loopback interface plus one resolvable public name, DNS only, no requests
- While offline the retry waits and re-checks every `offlineCheckMs` (15s) without using up **Max consecutive**, then continues through the normal grace period and cooldown
- Server errors (5xx, 429) are not held. A message from you, a new turn, a pause or switching the session off cancels the hold
- With `HTTP(S)_PROXY` / `ALL_PROXY` set, only interfaces are checked, so a proxy-only network is never mistaken for offline
- On by default (`pauseWhenOffline`); turn it off in **Retry strategy** to keep the old behavior

## Autonomous loop round limit

Also from [#81](https://github.com/HsiangNianian/dsh-auto-continue/issues/81)

- `loopMaxIterations` caps autonomous rounds per session; `0` (the default) means no limit
- When reached, the loop stops and reports it once: a log line, plus a browser notification when notifications are on
- Sending a message yourself or turning the loop back on starts the count over

## Child sessions and goals after a restart

Requested in [#77](https://github.com/HsiangNianian/dsh-auto-continue/issues/77) and contributed in [#80](https://github.com/HsiangNianian/dsh-auto-continue/pull/80). All three switches are off by default

- **Wake child sessions after restart** (`resumeInterruptedChildren`): when the startup scan finds subagent or team-member sessions a restart cut off, their root session gets one message listing them, so the parent decides what to continue. Children are still never resumed directly, parents you stopped yourself are never woken, and only interruptions inside the scan window (`freshMs`) count
- **Re-arm goals disarmed by a restart** (`resumeGoals`): after an auto-continue send, re-arm an `active` goal the host disarmed, so its continuation rounds run again. This authorizes on your behalf, hence opt-in
- **Resume paused goals** (`resumePausedGoals`): also resume goals you paused by hand; needs `resumeGoals`

## Plugin message source

From [#79](https://github.com/HsiangNianian/dsh-auto-continue/pull/79): **Send continue messages with plugin source** (`usePluginSource`, off by default) marks continue prompts as `plugin:dsh-client-auto-continue` instead of `user`. Echo matching accepts both

## Upgrade

Let current work finish, stop DSH, then update the profile you use

```bash
dsh plugin --profile web add dsh-client-auto-continue@0.18.0
dsh web
```

Desktop app users should update through the app's Plugins page and restart the app, since it uses its own profile

- Reload open browser tabs after restarting so the settings page shows the new fields
- Existing settings, session modes and pauses stay in place. The offline hold is the only new behavior that is on by default
