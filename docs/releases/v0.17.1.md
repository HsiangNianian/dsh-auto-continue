0.17.1 fixes the cramped phone input reported with DS-Bot and dsh-pocket in [#72](https://github.com/HsiangNianian/dsh-auto-continue/issues/72), and brings the rollback and prompt-variable fixes from 0.17.1-rc.1 to the stable channel

## Room to type on phones

DS-Bot changes the composer row to `display: contents`, which removes the size query container our compact layout relied on

- Add a viewport fallback at 460px and below, keeping the control compact even without a working query container
- Show the refresh icon, original switch and menu arrow, with full mode names available in the menu
- Keep pause notices and legacy save errors below the controls so they do not squeeze the input again
- Preserve accessible names, disabled states and the switch's touch target
- Keep the existing container queries for narrow composer panes on wider screens
- Cover both the host menu trigger and the legacy select fallback with the same styles

In the 351px Chromium reproduction, the control shrank from 194px to 77px and the input grew from 4px to 121px

## Rollback compatibility

The fix from [#69](https://github.com/HsiangNianian/dsh-auto-continue/issues/69) is now included in a stable release

- Skip `@240xu/dsh-message-ops` maintenance turns in silent recovery and autonomous followups
- Cancel automatic sends queued before a rollback
- Keep maintenance turns out of recovery statistics and preserve the existing retry budget
- Apply the same exclusion to startup scans of loaded and stored sessions, including unfinished maintenance turns

This check uses the verified `message-ops` marker; normal turns with other reason values remain eligible for recovery

## Missing prompt variables

With error classification enabled, errors such as `prompt variable "{{model}}" has no value for this assembly` stop automatic retries and use the existing permanent-error notification

The missing variable still needs to be fixed in the host configuration, and explicit retryable-error overrides still take precedence

## Validation and limits

- Type checking, build, the full regression suite and the pinned DSH plugin checker
- Existing DSH runtime compatibility, settings, migration and startup recovery tests
- Chromium layout checks at 320, 351, 390, 460, 461, 768 and 1280px, plus a narrow composer in a wide viewport
- Working, missing and `display: contents` query containers, English and Chinese labels, both menu paths, paused, saving, read-only, disconnected and legacy save-error states
- Real DSH 0.2.1-rc.3 host components with message-ops 0.11.8 and a deterministic model adapter: no extra model call after rollback in recovery or autonomous-loop mode, and no automatic retry for the missing-model case
- Native settings form and stable/prerelease publishing regression coverage carried forward from rc.1

The mobile checks use the actual plugin component with a minimal composer scaffold and the relevant DS-Bot/Pocket styles, not a complete Android installation or a full host menu implementation

The reporter's exact plugin/browser versions and an Android device have not been tested

## Upgrade

This is a stable release on `latest` for npm and GitHub Packages

Let active work finish and stop DSH, then update the plugin in the profile you use

```bash
dsh plugin --profile web add dsh-client-auto-continue@0.17.1
dsh web
```

Reload the browser after restarting DSH, including the remote page opened through dsh-pocket

For the desktop app, update the plugin in the app's own profile and restart the app

Existing configuration, conversation modes and pauses stay in place
