The composer control is compact again, with a native mode menu, an icon-only phone layout, toast feedback and a cleaner settings page

The per-conversation modes from 0.16.0 are unchanged under the hood; this release is about making the control fit the rest of the composer again

## A compact switch with a native mode menu

The wide 0.16 selector is replaced by the compact switch, now paired with the host's own menu primitives ([#67](https://github.com/HsiangNianian/dsh-auto-continue/issues/67), [#68](https://github.com/HsiangNianian/dsh-auto-continue/pull/68))

- The switch turns auto-continue on or off for the current conversation; turning it back on selects **Follow default**
- The menu next to it shows the current mode and opens **Follow default**, **Off**, **Recovery only** and **Autonomous loop**, with a check mark on the active choice
- The refresh icon identifies the control when the text label is hidden
- Keyboard access, immediate saves, cross-tab sync and per-conversation scoping are preserved
- Hosts without the `Menu` primitive keep a native `<select>` fallback

## Matches the composer on phones

The label collapses to its icon and the mode menu to its arrow with the same composer container query as the native permission picker

- The switch stays on one line with the other composer controls on narrow phones
- No separate viewport breakpoint: the control follows the composer row, like its neighbours
- The mode menu is still one tap away and shows the active choice

## Toast feedback instead of red text

- A failed session-mode save shows the host's toast instead of red text in the composer
- Saving and disconnected states keep the controls disabled and explain themselves through the tooltip
- A host that stays unavailable for three seconds announces itself once; a normal page load does not flash a toast
- Hosts without the `Toast` primitive keep the inline text fallback

## Native settings page

- The settings fields, switches and default-mode selector now use DSH's own `SettingsForm`, `SettingsValueField`, `Switch` and `SegmentedControl` primitives, so the page matches the rest of the plugin manager
- The category navigation and the status panels stay, while the custom field layout and the OS-level select popup are gone
- Older hosts without those primitives keep the previous card
- The plugin title and description are localized through `locale` metadata, so Chinese shows **自动继续** and its Chinese description
- Removed the charcoal header banner, but kept the GitHub invitation as a lightweight star link row
- Fixed a styling leak from the composer's invisible select onto **Default session mode**, which had stretched that select over the whole app and opened a selector on every click until a reload

## Validation and compatibility

- Type checking, build, the full regression suite and the pinned DSH plugin checker
- Settings and compatibility checks against published DSH `0.1.7-rc.2`, `0.2.0-rc.1`, `0.2.1-alpha.1` and `0.2.1-rc.2` packages, using the existing fixtures
- Composer mode menu, native fallback, container-query collapse, save failures, toast fallback and the settings select placement
- Native settings rendering, field editing, save, reload persistence and localized plugin metadata
- Runtime tests use controlled agent events and a deterministic model fixture, with no calls to an external model provider

## Upgrade

Let active work finish and stop DSH, then update the plugin in the profile you use

```bash
dsh plugin --profile web add dsh-client-auto-continue@0.17.0
dsh web
```

Reload the browser after restarting DSH so it loads the new composer control

For the desktop app, update from its **Plugins** page and restart the app, since updating the CLI's `web` profile does not update the desktop profile

Existing configuration, conversation modes and pauses stay in place. The settings card no longer shows the header banner; the plugin name and status remain in the plugin manager
