0.17.2 fixes the Chinese fallback seen with third-party UI languages such as Russian, thanks to @kesha4's contribution in [#73](https://github.com/HsiangNianian/dsh-auto-continue/pull/73)

## Language fallback

- Use Chinese for `zh` and `zh-*`, ignoring case, and English for every other or unset locale
- Apply the same rule to browser settings synchronization, host prompts and settings-save notifications
- Keep prompts in English even if an older tab writes `ru` back after the browser's three-write limit is exhausted
- Preserve custom prompt text and the existing limit on locale writes
- Rebuild the source map with LF line endings and enforce LF for text checkouts

## Upgrade

This is a stable patch release on `latest`

Let active work finish and stop DSH, then update the plugin in the profile you use

```bash
dsh plugin --profile web add dsh-client-auto-continue@0.17.2
dsh web
```

For the desktop app, update the plugin from the app's Plugins page in its own profile, then restart the app

Reload all open browser tabs after restarting the host so they pick up the new client too

Existing custom prompt text is preserved, so clear any text override you want to follow the built-in language defaults

If an older tab has left `ru` in the stored settings, the updated host already treats it as English; the field does not have to be rewritten for the prompts to work

**Behavior change:** profiles without a locale now use English until a Chinese UI locale is mirrored; explicit `zh` settings stay Chinese

## Validation

- Type checking, build and full regression suite
- DSH runtime compatibility, profile settings, migration and startup recovery tests
- Twelve locale and missing-value cases, plus mixed old/new tabs exhausting their write budgets
- Settings-save notifications and unchanged custom prompts
- Repeated builds produce identical artifacts, with LF source-map content matching the source files

The reporter's exact third-party language pack and a real Windows browser have not been tested
